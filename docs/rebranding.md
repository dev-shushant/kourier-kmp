# Kourier → AppArmorX Resilience

The product name is now **AppArmorX Resilience**, within the **AppArmorX** umbrella. Existing releases stay available and usable. This branding update covers documentation, inspector/settings copy, notifications, sample display names, export filenames and report headings, and publication descriptions.

## Existing integrations

No dependency or source migration is required. Continue using:

| Surface | Compatible identifier |
| --- | --- |
| Android Maven group | `dev.shushant.kourier` |
| Android artifacts | `kourier-android`, `kourier-noop`, existing component artifacts |
| Kotlin imports and facade | `dev.shushant.kourier.*`, `Kourier` |
| Swift products and imports | `Kourier`, `KourierIos`, `KourierSwift` |
| Binary release asset | `KourierIos.xcframework.zip` |
| Source repository | `dev-shushant/kourier-kmp` |
| Distribution repository | `dev-shushant/kourier` |
| Public Maven repository | `https://raw.githubusercontent.com/dev-shushant/kourier/mvn-repo` |

Database/cache names, FileProvider authorities, notification channel/category identifiers, bundle/application IDs, and URL schemes stay stable. Updating the brand does not clear existing traffic or reset channel preferences. Existing screenshots and videos may show Kourier; documentation identifies them as legacy captures.

New diagnostic exports identify AppArmorX Resilience as their creator, use `AppArmorX_Resilience_Export` for batch filenames and `apparmorx_resilience_` for individual files, and carry the new text report headings. HAR schema and traffic fields retain their existing format. Consumers depending on old human-readable headings or filename prefixes should update those expectations.

## Branch and release strategy

The rebrand is prepared on `codex/apparmorx-resilience-rebrand`, independently in source and consumer distribution. No existing version tag or binary is replaced. Merge and publish through the normal reviewed release process when ready.

Start roadmap implementation on a separate feature branch from the reviewed rebrand commit. Complete the blueprint's baseline audit before changing networking behavior. Preserve the working release and keep new fault controls out of release builds. Any future Maven/Swift namespace migration requires an explicit compatibility and no-op parity plan.

## Public rollout

Consumer documentation is maintained in the distribution repository, not generated by the source release script. Both repositories have a local rebrand branch. The publication script adopts new release titles and POM descriptions while retaining artifact paths and Swift products.

Website changes, GitHub repository display metadata, and updates to earlier LinkedIn/Medium posts are separate publishing tasks. Use “AppArmorX Resilience, formerly Kourier” for continuity. The proposed website page is `apparmorx.com/resilience`; this repository does not contain or deploy the AppArmorX website.

See [brand guidelines](brand-guidelines.md) and the [product blueprint](product-and-engineering-blueprint.md) for messaging and planned capabilities.
